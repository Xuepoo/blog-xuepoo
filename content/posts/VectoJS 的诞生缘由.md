## 背景

做个简单的自我介绍，我是一个独立开发者，你们可以称呼我为 Xuepoo(读法为 Swepoo,是我初中的时候取的名字)，我现在还是本科大三，下个学期（也就是这个暑假之后）才是大四，我是最开始大一学的 Java Web 后端出身的，这三年来的经历就不细说了，主要涉及的领域比较广，如 Web 后端、计算机网络、云计算、Linux、大数据技术，对计算机的很多领域都很感兴趣。

在今年上半年我做了很多开源工具，其中有一个叫作 [vectomancy](https://github.com/Xuepoo/vectomancy) 的程序，这个是一个可以将图像给转换成数学公式的程序，具体相关的介绍可以看这个仓库的 README 和 [vectomancy 在线网站](https://vectomancy.xuepoo.xyz/) 或者 [vectomancy 使用文档](https://blog.xuepoo.xyz/posts/vectomancy-jie-shao/)。

这个算是我第一个正式的完成度很高的开源程序，有完整的各个功能，并且在 crates.io, AUR, homebrew, scoop, dockerhub 上面都有对应的包。最开始的时候这只是一个 CLI 程序，然后我把这个编译成了 WASM 然后可以在网页端在线直接使用，这样更方便使用，那个时候还没有这么多的功能。

然后我就想着是不是可以把原本的转换图像的功能给扩展，然后就扩展了新的两个功能，分别是转换文字和转换视频，其中转换文字可以将输入的文字和选择的具体的字体给输出成对应的数学公式，然后这样的话这些就可以在海报、广告、字幕等等场景使用了，这是我最开始想到的这个的价值，然后转换视频的功能倒没有太多使用的场景，最多是觉得算是一个玩具功能吧。

我是一个独立的开发者，对开源程序这个社区很感兴趣，而且结合我自身的很多兴趣爱好，而且我看了很多 neocities 的各个自由开发者自己做的网站，我想的是自己应该也得有自己的个人网站才对，因为我不是一个跟风追随潮流的人，所以我觉得如果我做个人网站一定需要有很强个人辨识度而与众不同。

## VectoJS 的雏形

因为 vectomancy 是我个人的第一个完成度很高的开源程序，所以我才会花很多时间在这个上面，比如我加上了转换文字和转换视频的功能，给网站加上了很多渲染的优化，加上了 GPU 加速等等，所以在开发个人网站的时候我就想的就是也使用上它。

因为我的个人爱好比较多，比如漫画、推理小说、数学、动画、音乐等等，所以我就想把这些给展示到个人网站，然后我就把很多动画角色、文字、自己感兴趣的内容用 vectomancy 转换成装有数学曲线方程的 JSON 格式，因为这样使用图案来代替文字表达也算是一个特色吧，然后把这些作为伪图片渲染出来，而且这些可以加上拖动和点击跳转链接这些交互功能，但这些都不是最重要的，我觉得最重要的就是这个网站的 body 中只有一个 `<canvas>` 元素，整个页面就是一张图片，随时都可以右键作为一张图片来打开。

这里就引出来了一个 Zero DOM 或者说是 DOM Less 的说法，因为这个网站因为没有 DOM，那么就可以减少很多资源，比如 RAM, CPU 之类的占用了吧？我在这个时候并没有想的太多。

这个网站现在正在 neocities 上面进行部署的，大家随时都可以打开，地址为 [Xuepoo' Website](https://xuepoo.neocities.org/)。

## VectoJS 项目的建立

在网站搭建好了之后我应该在一个多月都在忙别的自己的项目，因为我自己个人做的开源程序比较多，有的是很麻烦的项目，在其中一个很难的项目中，这个项目需要跑大量的数据，然后需要不断测试调优，在这个项目我做的太累了，就想着去做做别的，去维护我别的项目了。

然后我的目光再次放到了 vectomancy，然后再结合着那个个人网站，我想的是这些是不是可以做成一个 UI 框架呢，也就是以 vectomancy 作为核心，然后把输出的数学方程曲线直接渲染到网页上面的那种，全程不使用 DOM 节点，全部渲染到 Canvas 上面。

最开始我想的是比较简单的，也就是直接把一堆数学公式直接给渲染到网页上面罢了，但是我发现我的这个网站在不同端的适配是不一样的，比如在电脑端是正常的，但是在移动端的浏览器显示的排版是不一样的。

这时候我注意到了今年三月底的一个 Web 前端明星项目—— [Pretext](https://github.com/chenglou/pretext)，这个库解决了在网页中文字重排的很多问题，具体我就不介绍了，大家应该都知道。所以我才想的是既然文字可以在 DOM 中正常排版，那么是不是也可以在 Canvas 上面进行排版呢，而且也可以自动排版呢。也就是在这个时候，这个项目诞生了，但是最开始并不是叫作 VectoJS，而是叫作 VectoUI，因为我当时给它的定位是比较模糊的，我觉得只是一个 UI 组件库，在后续我对它的定位才不断的发生转变，从最开始的组件库 -> 布局引擎 -> Canvas 运行时。

在这期间我学习了非常多的东西，比如浏览器渲染原理、字体文件的组成、DOM 本身相关的内容、浏览器内核计算、WebGL/WebGPU、Web Worker 等等，其实这个是我第一次正式接触前端，我以前只是学了前端的基础的东西和 Vue/React 框架和各个构建工具而已，但是我现在做的是跟前端相关的东西，太反差了。

顺便插上一句，我对数学很感兴趣，所以我在做项目的时候很多会往数学相关的进行考虑，比如 vectomancy 这个工具最开始我想的就是数学驱动的而不是数据驱动的，因为给图像转换成数学曲线使用有监督的机器学习之类的也是完全可以做到的事情，但是如果是数据驱动的话就不好做出这种的工具了，vectomancy 计算的时间是非常快的，但是数据驱动的话就需要花费很多数据训练，而且计算需要大量的成本（如时间和资源开销）。因为我坚信在数学理论作为基石，一个程序不太可能会做的很差，这也是 VectoJS 的基石。

## VectoJS 的开发过程

这是我目前做过的规模最大的项目，而且也是最难的，里面涉及到了大量的数学计算和底层相关的东西，不过好在是 typescript 开发的，不像我以前很多项目都是 rust 作为开发语言。

最开始我想的是把 vectomancy 作为一个部分然后放到 VectoJS 中，但是我发现我们不是需要转换图片，而是直接把所有的东西作为 Canvas 渲染即可。其实这就是一个 ECS 架构，就是把传统的文档流式的前端开发变成像是开发游戏的那样，这里有个很好的比喻：

- 传统的 Web 前端开发：一个网页就是一个房子中的一个房间，我们想要什么就往里面加就像了，比如沙发、电视、桌子等等，这些都是一个个 DOM 节点，但是随着这些家具越来越多，那么就会变得越来越拥挤，当空间越来越小的时候，再加上一个新的家具就需要触发重排和布局抖动了，这也是网页渲染开销最大的部分了，也就是这个房间的所有的家具都得挪动才能容下下一个家具。
- 使用 VectoJS 后的前端开发：一个网页就是一个棋盘，然后我们开发就是在这个棋盘上面放棋子而已，这个棋盘就是一个 Canvas，然后我们可以在上面任意布局和挪动棋子，这样的开销是非常小的。

但是这是完全不够的，因为光是一个 Canvas 我们就无法进行交互了，如果交互都没有的话，那么这个项目就可以直接宣布停止了，但是在前端有一个 a11y，全称是 Accessibility，这个是 VectoJS 的护城河，这个可以理解成一个透明的 DOM，目前主要应用在键盘导航与焦点管理、屏幕阅读器等等有限的领域。在 VectoJS 中，每一个组件都是有自己的坐标的，然后我们还有原生的 UI 组件，对于需要交互的组件我们只需要给它加上这个 a11y 就可以赋予它比拟原生 DOM 的效果了，而且是 agent 友好的，可以使用各种的自动化工具进行测试的，比如 playwright, selenium 等等。

借鉴了 Pretext 的冷热分离，VectoJS 也有属于自己的冷热分离，因为就像是开发游戏一样，每一个组件都变成了一个 Sprite，这个部分就参考了 PixiJS 了，这里就不介绍这些了。简单地说就是一个组件都是有自己的坐标，其实很多是参考了游戏引擎的设计。

然后我们有原生的 UI 库，对标 HTML 的很多元素都可以在 @vectojs/ui 中找到对应的模板，然后可以通过面向对象的开发进行自定义，而且支持 Markdown 渲染，流式处理（如大模型流式输出、实时大屏）。然后在动画这一部分做了很多，我们不仅支持原生的贝塞尔曲线，还主推使用弹簧动画，这也是一个特色。从这开始，就几乎可以实现所有的原生 DOM 的所有的功能了。

开发过程就讲这么多了，具体的实现细节就不多说了，什么大量的各种测试、应用场景、兼容性什么的就不多说了，剩下的直接去看 [VectoJS 官方网站](https://vectojs.org) 吧，里面的文档都说的挺清楚了。

## 开发总结

我并不是一个前端开发出来的，而且现在我的年纪还很小，三个月前我还是 20 岁呢，我觉得能做出这么庞大的项目真是太厉害了。

为什么我能做出这种项目呢？我觉得有这么几点：

1. **过硬的数学功底**：我从初中到现在的数学一直很好，平时都会没得事情的时候去解微积分，所以我才有创作 vectomancy 的动机并且真做出来了。
2. **丰富的开发经历**：我在大学三年来做的东西非常多，你们可能只能看到我做的开源的东西，其实我在老师参与的校内项目和校外项目都是有的。但是在大三上学期做完那些后我就开始作为独立开发者开发自己感兴趣的开源项目，而且我自己做的这些开源项目都是根据自己兴趣来解决某个特定的领域的问题的程序，而且都是可以发布到 crates.io, PyPI 上面的那种，我现在自己的 AUR 上面都维护了很多个程序。
3. **计算机领域知识广**：我对计算机的很多领域都是很感兴趣的，我是大一学的 Java 后端，但是我之后接触的很多都不是 Java 后端，我很喜欢 Linux，我自己的电脑系统就是 Linux 操作系统，然后我还喜欢云计算，比如我的网站全都是部署到 Cloudflare 上面的，然后我的一些服务是在 AWS 和 GCP 上面的，然后还接触过大数据技术如 Spark, Flink 这种的。学习过的语言就有非常多，比如 Java, Python, Rust, Golang, JavaScript/TypeScript, Lua 等等。
4. **不断在创作中积累**：因为我涉及的领域非常多，所以学习的东西就会非常多，使用到的开发工具、开发的技巧什么的都在不断的积累，而不是用到什么就去查了，比如我的 vectomancy 是 Rust 开发的，就会有很多工具链和开发技巧，在开发后续的跟 Rust 相关的程序也就可以可以直接按照模板搬过去了。比如我的 WASM 编译的时候因为我电脑是 CachyOS，所以有默认优化编译的，所以在项目的 .cargo 目录就需要写配置文件去关闭这个优化，然后在之后我别的项目中遇到的时候就会提前去写好这个配置文件了。
5. **创新的动力**：我想要开发的东西太多了，到了现在其实我还有很多我想做的创新的东西，但是没有时间去做了。但是创新这一点并不是凭空出来的，这都是在我之前说的那几点的积累才出来的。毕竟我都不是一个前端开发工程师，但是我做的最大的东西是跟前端相关的 😄，可真是讽刺啊。

在之后我肯定会不断维护 VectoJS 的，我现在自己开发的网站都是 Dogfooding 在直接使用 VectoJS Native 的，我现在正在开发几个跟这个 VectoJS 对口的项目。

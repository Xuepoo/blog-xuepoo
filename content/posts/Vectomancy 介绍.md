## Vectomancy 介绍以及动机

Vectomancy 是一个可以将图片，如 `.png, .jpg, .svg, .webp` 等等文件都可以转换成对应的数学曲线的开源工具。

这个项目的灵感来源于 Wolfram Alpha 中的 math art，里面使用了数学方程来在二维坐标系上面画出了很多出名的人物的轮廓以达成实现用曲线画画的效果。然后就是这个我之后还想着 GeoGebra, Desmos 这些也可以做到，不过后者 Desmos 是做了很多 Math Art 的，但是跟我们的这个不一样，Desmos 有非常多的使用数学来实现的各种艺术形式，但是跟我们的这个有一些区别。然后我又参考了一些别的项目，比如可以使用傅里叶变换来画出图像，在 GitHub 上面也确实有相关的仓库，但是很多其实都是一个简单的 Demo，并不是一个完成度很高的程序，而且计算很慢，参数也不是很多，而且还有的项目竟然是需要训练模型然后再慢慢画出来的，我看这些代码基本上都是 Python 来写的，反正就是非常慢。

![WolframAlpha](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623204250.webp)

因为我对数学比较感兴趣，然后我觉得我的想法比较好，所以我就研究了很多这些相关的东西，比如计算机图形学、图像处理等等邻域的东西，然后最后确定好了方向，我们这个程序可以将栅格位图转化为纯正的参数方程，不是传统的像素转成像素，而是转换成纯数学公式。而且我们的是数学驱动的，而不是像机器学习那样的数据驱动，所以计算会很快。

Vectomancy 支持三种模式，分别如下：

- Spline (贝塞尔样条)：用高精度的控制点拟合平滑的工业级曲线。
- Fourier (傅里叶级数)：将复杂的轮廓转化为无数个互相嵌套、匀速旋转的圆圈（Epicycle），实现单线作画的极致浪漫。
- Chaikin (切角算法)：生成极具手绘感、有机质感的平滑多段线。

然后用户可以通过很多的参数，来调整输出的结果效果，比如 `--color, --detail, --min-path-len, etc` 等等，

![终端输出](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623192159.webp)

效果如下：

![这是随便找的一张b站评论区的图片](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623192422.webp)

我这个最开始我是想的支持非常多的输出格式，比如 `Wolfram, Julia, GeoGebra, Scratch` 等等，但是发现这些支持都不是很好，其实主要是方程太多了，然后这些渲染和运行效果不好，所以就在后续的版本给移除了，在早期版本，比如 v1.x.x, v2.x.x 应该还是有的。

![输出成 desmos ](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623203405.webp)

因为笔者使用 Linux 使用的比较多，所以很多东西考虑的还是比较全面的，比如配置文件会放到 `$XDG_CONFIG_HOME/vectomancy` 中，然后还支持 `--config` 这种直接引用 .toml 的配置文件，然后还支持 `completion` 这种支持 `bash, zsh, fish` 的自动补全，配置文件可以看仓库中的 docs 目录，里面有相关的配置，这样的话使用本地的 cli 工具就可以直接输出配置文件中的配置了，比如输出目录，是否用了 GPU 加速，输出的图片的参数选择等等。

之前也提到了，就是 GPU 加速，我最开始是考虑了设计这个东西的，然后在 v3.x.x 版本后就加上了，我自己的电脑是 Nvidia 的独显，所以用的是 CUDA，但是不能只考虑我自己的，也就是还需要考虑 AMD 和 Mac 的用户，所以之后还是换成了统一的 wgpu，然后也加入了并行计算、批处理等等功能。
> 其实对于很多用户来说这个 GPU 这个模式没有必要开启，我们的这个程序使用的是 Rust 作为开发语言，所以本身就非常快了，然后我们这个是纯数学驱动的，而不是数据驱动的，所以很多时候计算一张图片是非常快的，很多时候都是在一两秒就可以计算出来的，很多时候使用并行计算和使用 GPU 反而变慢了，比较启动 GPU 还需要花时间等等因素。

我这个程序现在可以通过很多方式安装，如果用户本地有 cargo 的话，还是比较建议直接使用 `cargo install vectomancy-cli` 的，然后针对不同的操作系统也有对应的安装方式，比如在我自己用的 Arch Linux 系，可以通过 `yay/paru -S vectomancy` 来安装，然后对于 MacOS 可以通过 homebrew，Windows 可以通过 scoop 安装，而且还可以通过 Docker/Podman 来直接 Pull，因为我是上传到了 Dockerhub 上面的，只是需要注意需要提前加我的 tap/bucket，详细的可以看 [https://github.com/Xuepoo/vectomancy](https://github.com/Xuepoo/vectomancy) 里面的 releases，因为我都是准备好了的，优先下载最新的版本就行了。

## 应用

一开始我的这个灵感只是因为可以将任何的图片转换成曲线，也就是把一个卡通人物给变成一堆数学方程来表示，然后做完后发现这个能应用的功能其实很多的，而且还比我之前参考的那些开源仓库更厉害，比如我们的这个是可以处理非常复杂的图片的，比如一张分辨率非常高，有非常多细节的图片等等，比如如下这张梵高的《星夜》：

![梵高《星夜》](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Starry%20Night.webp)

然后就是这张图片是可以将图片的背景给去除的，比如以下原图和处理后的图片对比：
![原图](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623202049.webp)
![处理后的](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623202105.webp)
然后因为我们这个主要还是展示图片的轮廓，所以对于临摹来说很好用，直接代替人工临摹了属于是。

然后因为我们输出的其实并不是像素，我们输出的是数学公式，所以这个是一个比较特殊的文件转换，没人会想到一堆数学公式竟然可以组成一张图片，这个应用可以看我自己的 [个人网站](https://www.xuepoo.xyz) 是如何实现的。

当然还有很多其他的应用场景，而且我的这个是一个 CLI 程序，可以直接下载二进制的文件，不需要解释器和虚拟机运行时，所以在很多边缘计算场景都是可以使用的，也有一定的扩展性（详细看下文）。

## Vectomancy Website 介绍

以上我说的都是本身这个 vectomancy 程序，这个只是一个 CLI 程序，只是在终端可以进行操作，但是对于大多数人来说就用不到终端，而且终端上面的体验并不是很舒服，所以我就开发了对应的网页端，我最开始是想的从好几个 GUI 形式进行开发的，但是最优解是静态网页 + WASM，前端我是使用的 Zola 构建的静态网页，然后后端我是把我的 CLI 程序给编译成了 WASM（这个编译后的大小很小，只有 2MB 左右），然后用户只需要访问我的这个域名 [https://vectomancy.xuepoo.xyz](https://vectomancy.xuepoo.xyz) 既可以直接使用了。

![网页端首页](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623194323.webp)

然后用户就可以进入 Image 页面就可以体验我们程序的功能了。

![Image 页面](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623194526.webp)

用户可以通过左侧栏来操作了，我最开始是想着像 ComfyUI 的 Web 端那样，但是我还是自己设计了一种操作方式，以下是介绍下各个用法（其实右上角的 "?" 就可以弹出帮助页面）

- **导入**：用户可以通过好几种方式进行导入，
  - **本地**：用户可以直接使用本地的图片。
  - **URL**：用户可以直接输入 URL，然后我们导入的时候就相当于用户直接去这个图片链接进行 fetch。
  - **直接粘贴**：我们是支持 `CTRL+V` 这种的直接粘贴图片的，这其实是最方便的，我自己测试的时候都是这么做的，选用一张比较感兴趣的，然后右键这个图片，然后 `copy image` 然后直接来我们的网页进行粘贴就可以导入了。
- **设置参数**：这里面其实就包含了很多 CLI 就有的参数了，这里就不做具体的介绍了。
- **导出**：支持图片（png, jpg）导出，然后也支持 JSON 格式，因为 JSON 格式是最通用的，可以方便以后做别的功能。
然后用户可以放大图片，然后删除图片之类的很多功能，我已经考虑了很多功能了，如果还有什么建议可以在首页的 Feedback 发送你的反馈。

>PS: 最开始我的网页是有画廊 Gallery 这个功能的，但是为了规避版权风险，所以我就关闭了这些。
>然后很多时候一张图片在切换明暗主题会有不同的效果 (つ´ω\`)つ

## 拓展插件

在正式版做完后，我考虑了一些别的东西，也就是转换文字和视频，这两个我都实现了，所以现在可以看到 `vectomancy image/text/video` 这几个，我来介绍下这两个。

### Text

我最开始想的是我们可以将我们的输入变成文字，然后输出也是这些数学公式，但是这些是根据字体来转换的，比如我是用的是 8bit 的像素字体，那么输出也是对应的文字，但是这个输出可以改变大小，我们可以将这个输出应用在海报、网页设计上面。

![Text 页面](https://cdn.xuepoo.xyz/blog/posts/Vectomancy%20%E4%BB%8B%E7%BB%8D/Pasted%20image%2020260623195634.webp)

### Video

这个其实只是将核心功能处理更多的图片，因为一个视频就是由非常多的帧图片组成的，那么我们这个就是将输入原来的图片变成一个视频罢了，只是注意我们的网页端把这个功能给砍掉了，因为网页端处理的非常慢，这主要是因为网页用的单线程，所以要体验这个功能的就需要在本地用 cli 工具来做了，而且在后台进行就行了，这个是支持多线程并行处理的，然后如果输出的视频想要是透明的视频，那么输出的格式需要是特定的格式。

我的 Bad Apple!! 就是这么转换的，当然大家还有什么建议可以随时提到 feedback 中。

## 注意事项

- 图片的输出的质量一般是看输出的方程的数量来决定的，也就是 PATHS，数量越多图片的细节就更多，但是输出的文件也会更大（只是 JSON 的格式输出会更大，如果直接导出成图片没什么影响）。
- 图片的质量决定了输出的上限，也就是图片本身的元素，比如分辨率、颜色之类的会影响着输出的结果，比如分辨率可以通过一些工具转换成更高分辨率的图片（如 waifu2x）。
- 使用网页端的时候，如果是 Firefox/Safari 的话，就会出现下拉菜单是没有被 CSS 渲染，这个是浏览器内核的问题，然后还有一个就是如果要使用字体的功能的话，对于访问本地字体就需要使用 Chrome/Edge 这种 Chromium 内核的，因为 Firefox/Safari 不允许访问本地的字体。
- 如果有什么问题和建议的话，可以在网页端的首页的右下角的 Feedback 发送反馈，或者联系作者也行。
